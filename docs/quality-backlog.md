# Kheyflix quality backlog

This living backlog is evidence-driven. Items move only after a reproduced defect, a focused regression, and production-safe verification.

## P0 — release blockers

1. **Automated exact-release first-frame integrity:** The exact `b1d32aa12dddca31f5c7a2e9d599e2f1f751d400` production workflow passed its real-catalog playback gate: first decoded frames were 960–998 ms (phone) and 714–732 ms (laptop), followed by four advancing timeline checkpoints. The production verifier also reported 690 catalog records, 454 ready titles, and 3,659 video files. Every later merge still needs the same exact-commit gate.
2. **Authenticated production journey:** The controlled, server-side access gate is implemented and the exact production workflow verifies it without exposing a credential. The final user-ready sign-off still needs an authenticated browser session to exercise the catalog and playback journey manually; no configuration value is recorded in this repository or backlog.
3. **Manual exact-release Safari playback:** A real live-catalog title decodes and advances continuously in local macOS Safari and the iPhone simulator, but production Safari currently presents the access gate with no authorized session. Capture first decoded frame and sustained, advancing playback on authenticated laptop Safari and iPhone Safari against an exact deployed merge. Chromium device emulation and a rendered player are not substitute evidence.

## P1 — reliability and performance

1. **End-to-end playback startup budget:** One absolute, configurable `KHEYFLIX_STREAM_STARTUP_TIMEOUT_MS` deadline now spans AllDebrid resolution, DNS, relay/direct transport, first media byte, and one safe recovery. The existing first-byte setting remains a shorter per-attempt cap, never a reset of the overall budget. Coalesced resolver jobs track individual viewers: one canceled viewer detaches safely, while the final viewer aborts provider work and late provider results cannot unlock or cache a link. Keep exact-release first-frame and continuous-playback verification mandatory for every delivery.
2. **Exact-release capacity and recovery proof:** Bootstrap quality is preserved end-to-end; bounded native-HLS recovery, session handoff, prewarming, cancellation, and capacity release are covered locally. The local transcoder suite now proves that a stale encoder is fully released before its replacement is admitted, an abruptly disconnected queued request cannot consume the reclaimed slot, an explicit queued-session stop cannot later spawn, and a disconnected subtitle probe immediately releases capacity. Confirm the exact deployed revision has no false capacity `429`, stuck recovery, or leaked reservation; genuine full-capacity requests must remain retryable rather than oversubscribing the service.
3. **Cross-instance access throttling:** The local rate limiter deliberately ignores spoofable forwarding headers and only provides per-instance abuse friction. If this controlled service expands, move brute-force controls to a trusted, durable edge/identity service.
4. **Native Apple adaptive quality:** Auto deliberately preserves the proven 480p native-HLS session because replacing a live single-variant playlist interrupts Safari. Build a true multi-variant HLS manifest before re-enabling seamless automatic Apple quality upgrades.
5. **Provider resilience under real outage:** Retry classification, `Retry-After`, cancellation propagation, resolver deadlines, link refresh, preparation durability, and operation timing have focused regression coverage. Continue validating error copy and recovery behavior against non-destructive real-provider failures after release.
6. **Production observability retention:** The release adds safe operation timing and playback diagnostics. Establish retention, alert thresholds, and a privacy-reviewed aggregation path before treating the data as an operational SLO.

## Resolved / verified policy work

- **Railway MCP-only delivery policy (2026-08-29):** PR [#64](https://github.com/GDemay/Kheyflix/pull/64), merged as `1a0ae288b819cd6d05502ab2234bc14dace8daf8`, removed the direct Railway CLI/token path, added a policy regression test, and passed exact-head CI/CD plus independent production health and catalog verification. The deployment workflow now fails closed outside the approved Railway MCP process.
- **Provider access and direct-egress hardening (local, 2026-08-30):** Provider-backed API routes now require an opaque, signed HttpOnly `Secure; SameSite=Strict` browser session. Access-code comparison is constant-time, server-side only, and request bodies are bounded. The stream relay is the default, has a bounded first-byte deadline, refreshes one stale provider link before forwarding bytes, cancels abandoned work, and pins each outbound HTTPS connection to the public DNS answers it validated while preserving the provider hostname for TLS.
- **SSRF and verification-boundary review (local, 2026-08-30):** Independent review found that hexadecimal IPv4-mapped IPv6 literals could bypass the first DNS-pinning implementation. The relay now parses IPv6 address bits and rejects private IPv4-compatible, mapped, translated, NAT64, 6to4, and Teredo endpoints; regression cases include both dotted and canonical hexadecimal mapped loopback/private forms. The review also found that a staging verifier would request a production-audience OIDC token. That unsupported alias was removed and now fails closed until staging receives its own reviewed identity contract.
- **Provider and playback resilience (local, 2026-08-30):** AllDebrid/Prowlarr work has bounded retry and deadline behavior, coalesced/cache-aware resolution, operation timing, safe health reporting, and preparation polling that does not duplicate known magnets. Native HLS uses finite 15-second VOD windows with one bounded warm successor; the player distinguishes intentional handoff from rebuffering and permits one position-preserving recovery session before surfacing a terminal, actionable failure.
- **Native Apple HLS continuity (local, 2026-08-30):** Reproduced the Safari interruption caused by Auto 480p-to-original source replacement. Native Auto now holds the continuous 480p HLS path; pause/resume releases the old rolling playlist before starting a fresh one at the exact saved position. With the live-catalog title *Friends S01E01*, macOS Safari showed a decoded frame by 12.507 seconds and advanced from 3:15 to 4:32 over 80.451 seconds; the iPhone simulator showed a decoded frame by 7.552 seconds and remained visibly decoded after 70.264 seconds. Both runs crossed multiple 15-second VOD windows. After client cleanup, transcoder capacity returned to two available slots with zero startup timeouts, encoder exits, or capacity rejections. Exact-release production verification remains required.
- **Native-VOD teardown race (local, 2026-08-30):** Exact-head PR CI exposed a duplicate release of the old session during a finite VOD transition. The awaited replacement release and React cleanup now share an idempotent, bounded session-release registry; a failed awaited request still leaves cleanup free to send its best-effort fallback. The old active session is asserted to release exactly once, and the controlled laptop regression passed five consecutive repetitions.
- **Exact release verification (local, 2026-08-30):** The deployment verifier now fails closed when `EXPECTED_COMMIT` does not match public health, and the production workflow passes `${{ github.sha }}` into that assertion after its deployment wait.
- **Client-cancelled subtitle observability (local, 2026-08-30):** A browser teardown could previously be reported as a `502` subtitle/provider failure despite cancellation having been propagated correctly to the transcoder. The gateway now returns a non-failure `499` for a disconnected client, and shared request logging records pending cancellations at debug rather than warning/error level. The live audio/subtitle journey now completes without the spurious failure log.
- **Discovery total deadline and cancellation (local, 2026-08-30):** A browser-side 15-second search timeout previously left the server free to start a second Prowlarr pass and up to 28 seconds of TMDB validation. Discovery now has one 14-second server deadline spanning scoped/fallback Prowlarr requests, retries, provider body reads, and validation; it forwards browser cancellation to each provider request, cancels sibling validation work, and records a `499` as debug rather than an error. A Safari-safe client signal bridge aborts a pending search on route exit without stale state or a user-visible failure. Regressions cover fallback cancellation, retry cleanup, a non-resetting deadline, stalled response bodies, sibling cancellation, the route contract, and phone/tablet/laptop/WebKit UI exit behavior. Exact production verification remains required for its delivery PR.
- **Cancellable provider DNS preflight (local, 2026-08-30):** A stalled `dns.lookup` could outlive the relay's three-second first-byte budget and later open a provider request. The stream path now uses cancel-capable A/AAAA resolver work tied to the request/deadline signal; both relay recovery attempts and explicit direct mode stop DNS at the deadline or viewer disconnect, and late answers cannot initiate a fetch or redirect. Regressions assert resolver cancellation, bounded `504`/`499` responses, and no late provider continuation. Exact production verification remains required for its delivery PR.
- **Deterministic startup-budget regression (local, 2026-08-30):** Exact-head CI exposed that the initial AllDebrid-resolution timeout regression relied on a real 250 ms timer and could be starved by the parallel test workload until Vitest's five-second ceiling. The regression now advances a controlled clock only after resolution begins, while preserving the exact deadline, `504`, abort-signal, and no-DNS/no-fetch assertions. This strengthens CI evidence without changing production stream behavior.
- **HLS client-abort handoff (2026-08-30):** PR [#78](https://github.com/GDemay/Kheyflix/pull/78), merged as `4dc39f38bd7243471d5c50ff0cf3a87043a0db2f`, closes the relay-body handoff where a client abort could arrive after the transcoder fetch settled but before the body listener attached. A deterministic regression resolves the response and aborts in that exact gap; the idempotent reader now cancels once. The exact-commit main CI/CD run `33315058441` passed with public health reporting the same commit and the real-catalog suite passing 8 checks with 2 platform-gated skips.
- **Discovery search supersession (local, 2026-08-30):** An in-flight search previously disabled its only replacement action, while changing Movies/Series left its old result current. A deliberate second submit now aborts and replaces the request, and a content-type change cancels it, clears stale results, and leaves the typed title ready for an explicit new search. Deferred-response regressions assert abort propagation, no stale render or client error, recovery of the submit control, and selected-type semantics across phone, tablet, laptop, and WebKit. Exact production verification remains required for its delivery PR.
- **Global search focus restoration (local, 2026-08-30):** Activating the global search control with a keyboard previously left focus on the unmounted opener instead of the newly visible search field. Opening the search route now transfers focus directly to the labelled title input; the focus handoff itself does not add a second scroll. Regressions cover keyboard activation, direct search routes, and history return across phone, tablet, laptop, and WebKit. Exact production verification remains required for its delivery PR.
